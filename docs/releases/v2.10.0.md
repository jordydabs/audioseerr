# AudioSeerr v2.10.0 — Security, reliability & request tracking

A full security, correctness and integration review of AudioSeerr — plus the features that make a request feel *finished*: **real album requests, fulfilment tracking, a Download Activity page and outbound notifications.**

> **⚠️ Upgrading is strongly recommended.** Two of the fixes below close bugs that could lose your data or hand out admin access.

## ⬆️ Before you upgrade

- **Set `JWT_SECRET` and `ADMIN_PASS` in `.env` before starting.** Both now ship blank in `.env.example`. Production refuses to start with a missing or weak `JWT_SECRET`, with a sample `ADMIN_PASS`, or — on a first start — with a blank one (`openssl rand -hex 32` makes a good secret). An existing install that already has its admin can leave `ADMIN_PASS` blank.
- Existing browser sessions keep working. Changing a password or a user's role now signs other devices out.
- `mem_limit` in `docker-compose.yml` went from `256m` to `384m` — use the new compose file.
- **No database migration.** Two one-time repairs run automatically at boot: request rows are re-linked to their owner by id, and any users sharing an id are reported in the log.

## ✨ What's new

- **Album requests really add albums.** Requesting a second album by an artist you already own used to do nothing in Lidarr while the request was recorded as delivered. Now that album is monitored — and the artist is created alongside it, unmonitored, when needed, so one album doesn't pull in a whole discography.
- **Fulfilment tracking.** Requests move on to **⬇️ Downloading** and then **🎉 Available** when the files actually land, with an *Available* counter tile and status filter. It rides on library data AudioSeerr already caches, so it costs Lidarr nothing extra.
- **Download Activity page.** A live view of Lidarr's queue: progress, indexer, time remaining, stalled and failed grabs highlighted — and admins can remove a stuck item.
- **Outbound notifications** to **Discord, ntfy, Gotify or any JSON webhook** on request created / pending / approved / rejected / available. Delivered server-side, so nobody needs a browser open.
- **Root folder & metadata profile selection.** Adds used to always land in Lidarr's first root folder; the requested quality profile is now validated too.
- **Backup, CSV export & retention.** Download a redacted `db.json` or a CSV of the request history, and optionally prune settled requests by age or count (pending and in-progress rows are never touched).
- **Deep links.** `/search`, `/downloads` and friends are bookmarkable; reload and Back work, and the Android back gesture no longer exits the installed PWA.
- Reject-with-reason in the UI, the running version in the sidebar, and Escape closes any modal.

## 🔒 Security

- **The weak-secret guard missed the secret the project shipped with.** Copying `.env.example` and changing only `ADMIN_PASS` booted a production instance signing sessions with a key published in this repository — effectively unauthenticated admin. The guard now matches every known sample and anything that reads like a placeholder, and a blank `ADMIN_PASS` is rejected on first start (it used to boot an admin account nobody could log in to).
- **Sessions are revocable.** Role changes, password changes and resets, and account deletion take effect immediately instead of when a year-long token expires. `SESSION_DAYS` sets the window.
- **`/api/summary` no longer leaks the whole instance** — every user's requests, usernames and the account and key counts — to any logged-in user. It is scoped to the caller; admins and API keys still see everything.
- **XSS fixed in artist/album tiles:** an apostrophe in a catalogue name could break out of an inline handler.
- **Dependencies patched, `npm audit` clean.** `proxy-addr` (critical — IP spoofing via IPv4-mapped IPv6 addresses and trusted subnets; it's the library behind `TRUST_PROXY`), `body-parser` (high — DoS on compressed request bodies) and `qs` (moderate — DoS) are on fixed versions, and Express is at 4.22.3.
- Credentials are no longer forwarded on cross-origin redirects, API keys are compared in constant time, login timing no longer reveals whether an account exists, and `POST /api/lidarr/search` is admin-only. See the [changelog](https://github.com/jordydabs/audioseerr/blob/v2.10.0/CHANGELOG.md#2100---2026-10-23) for the rest.

## 🛡️ Data integrity & reliability

- **No more silent data loss.** A syntax error, truncated file or permissions problem in `db.json` was treated as an empty database and overwritten by the next write. It now fails loudly and leaves the file untouched; writes are atomic, `fsync`ed, and keep a `.bak` generation.
- **A failed save no longer crashes the container** (it used to crash-loop).
- Collision-resistant request ids, daily limits that concurrent requests can't slip past, failed approvals that stay retriable instead of becoming dead ends, and a stale-cache fence so a connection change can't leave every add reading "already in library".

## 🔌 Upstream integration

- No more hung requests, artist names corrupted at network-chunk boundaries, or non-JSON replies accepted as success.
- MusicBrainz calls respect its 1 request/second limit and carry a contactable User-Agent; transient upstream failures are no longer cached as permanent empty results.

## 🐛 Fixes & polish

Navigation highlighting, a search that ran twice or showed out-of-order results, keyboard access to the sidebar and request pickers, a slider that over-scrolled, and a "New & Upcoming Releases" row that showed the same tiles as Trending Albums — it now uses Apple's most-recent feed (`APPLE_STOREFRONT` picks the country).

## 📦 Install

```bash
git clone --branch v2.10.0 --depth 1 https://github.com/jordydabs/audioseerr.git
cd audioseerr
cp .env.example .env           # then set JWT_SECRET and ADMIN_PASS
mkdir -p ./data && sudo chown -R 1000:1000 ./data
docker compose up -d --build   # → http://localhost:7575
```

Upgrading? Grab the new `docker-compose.yml`, set the two secrets above, and re-run `docker compose up -d --build`.
